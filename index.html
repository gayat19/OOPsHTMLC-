Class and Object

A class is a blueprint. An object is a real instance created from that blueprint.

In your project

internal partial class Account
{
    public string AccountNumber { get; set; }
    public string NameOnAccount { get; set; }
    public float Balance { get; set; }
}

Creating objects

Account acc1 = new Account();
acc1.NameOnAccount = "Ramu";
acc1.Balance = 2344.4f;

Account acc2 = new SavingAccount();
Teaching point: `Account` is the idea. `acc1` and `acc2` are actual account objects in memory.

Constructors

A constructor is a special method that runs automatically when an object is created.

Default constructor

public Account()
{
    // Runs when new Account() is called
}

Parameterized constructor

public Account(string accountNumber,
               string nameOnAccount,
               DateTime dateOfBirth,
               string email,
               string phone,
               float balance)
{
    AccountNumber = accountNumber;
    NameOnAccount = nameOnAccount;
    Balance = balance;
}

Constructor in derived classes

internal class SavingAccount : Account
{
    public SavingAccount()
    {
        AccountType = AccType.SavingAccount;
        Balance = 100.0f;
    }
}
Example: When you create `new SavingAccount()`, the account type and opening balance are automatically set.
04

Encapsulation

Encapsulation means keeping data and behavior together, and controlling how the data is accessed.

Data

`AccountNumber`, `NameOnAccount`, `Email`, `Phone`, `Balance`

Behavior

`ToString()`, `CompareTo()`, `Equals()`, repository create/update/delete methods

public float Balance { get; set; }
Improvement idea: In real banking apps, `Balance` should not be freely set from outside. Use private setter and methods like `Deposit()` and `Withdraw()`.
public float Balance { get; private set; }

public void Deposit(float amount)
{
    if (amount <= 0) throw new ArgumentException("Invalid amount");
    Balance += amount;
}

Inheritance

Inheritance allows a child class to reuse and extend a parent class.

Account↙SavingAccount↘CurrentAccount
internal class CurrentAccount : Account
{
    public CurrentAccount()
    {
        AccountType = AccType.CurrentAccount;
        Balance = 0.0f;
    }
}
Meaning: `SavingAccount` and `CurrentAccount` automatically get the properties of `Account`, such as `AccountNumber`, `NameOnAccount`, `Email`, and `Balance`.
06

Polymorphism: Static and Dynamic

Polymorphism means one name or reference can behave in different ways.

Static Polymorphism

Compile-time. Achieved by method overloading or operator overloading.

Dynamic Polymorphism

Runtime. Achieved by method overriding using `virtual` and `override`.

Static polymorphism: operator overloading from your project

public static bool operator ==(Account a, Account b)
{
    return a.AccountNumber == b.AccountNumber;
}

public static bool operator !=(Account a, Account b)
{
    return a.AccountNumber != b.AccountNumber;
}

Dynamic polymorphism: suggested improvement

internal class Account
{
    public virtual float CalculateMinimumBalance()
    {
        return 0;
    }
}

internal class SavingAccount : Account
{
    public override float CalculateMinimumBalance()
    {
        return 100;
    }
}

Account account = new SavingAccount();
Console.WriteLine(account.CalculateMinimumBalance()); // 100
07

Interfaces

An interface is a contract. It says what a class must do, but not how it must do it.

Customer interaction contract

internal interface ICustomerInteract
{
    Account OpensAccount();
    void PrintAccountDetails(string accountNumber);
}

Implementation

internal class CustomerService : ICustomerInteract
{
    public Account OpensAccount()
    {
        // collect details and create account
    }

    public void PrintAccountDetails(string accountNumber)
    {
        // print account details
    }
}

Generic repository interface

internal interface IRepository<K,T> where T : class
{
    T Create(T item);
    T? GetAccount(K key);
    List<T>? GetAccounts();
    T? Update(K key, T item);
    T? Delete(K key);
}
Why it is useful: `Program` can depend on `ICustomerInteract`, not directly on `CustomerService`. This makes code flexible and easier to test.
08

Abstract Class

An abstract class is a partially complete base class. It can provide common code and force child classes to complete missing parts.

internal abstract class AbstractRepository<K, T> : IRepository<K, T> where T : class
{
    protected Dictionary<K, T> _items;

    public abstract T Create(T item);

    public T? GetAccount(K key)
    {
        if (_items.ContainsKey(key))
            return _items[key];
        return null;
    }
}

Child class completes the abstract method

internal class AccountRepository : AbstractRepository<string, Account>
{
    public override Account Create(Account item)
    {
        // generate account number and add to dictionary
        return item;
    }
}
InterfaceAbstract Class
Only defines a contract.Can define common fields and reusable methods.
A class can implement many interfaces.A class can inherit only one class.
Example: `IRepository<K,T>`Example: `AbstractRepository<K,T>`
09

Indexer

An indexer allows an object to be accessed like an array using square brackets.

internal class AccountRepository : AbstractRepository<string, Account>
{
    public Account this[string index]
    {
        get { return _items[index]; }
        set { _items[index] = value; }
    }
}

How to use it

AccountRepository repo = new AccountRepository();
Account account = new SavingAccount();
account.AccountNumber = "1001";

repo["1001"] = account;       // calls set
Account result = repo["1001"]; // calls get
Teaching point: Internally it uses a `Dictionary`, but externally it gives a clean array-like syntax.

Trainer Summary

Best explanation flow

Start with `Account`, create objects, show constructors, then move to inheritance with `SavingAccount` and `CurrentAccount`.

Then explain design

Use `ICustomerInteract` and `IRepository` to explain contracts. Use `AbstractRepository` to explain reusable base logic.

Advanced part

Explain indexer, operator overloading, generics, partial classes, and dynamic polymorphism improvement.

Assignment idea

Ask students to add `Deposit`, `Withdraw`, `CalculateInterest`, and override behavior for savings/current accounts.

Final teaching line: OOP helps us model real-world business concepts as reusable, maintainable, and testable software components.
